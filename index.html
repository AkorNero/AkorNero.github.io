About

I'm an AI/ML engineer in Cork. Most of my work so far has been on retrieval systems and the tooling around LLMs: getting the right documents in front of the model, checking what comes out, and keeping it running.

I spent two years at LTIMindtree in Bengaluru, starting as a graduate engineer trainee. Generative AI took off just after I joined, so I learned a lot of it on the job: a production RAG assistant for insurance documents, the extraction pipeline and knowledge graph behind it, and Studio, the team's model portal, with the gateway and guardrails around it, all running on AWS.

In 2024 I moved to Ireland for an MSc in Mathematical Modelling and Machine Learning at UCC, because I wanted to understand the models better than I did. My research looked at making Kolmogorov–Arnold Networks smaller and faster to train.

Since finishing, I've built projects of my own (an agentic RAG assistant, a self-hosted vLLM inference service and an LLM evaluation harness), earned the AWS ML Engineer certification, completed LangChain and Anthropic MCP courses, and mentored first-time programmers at Django Girls Cork. I also work with coding agents such as Claude Code, including MCP servers, skills, hooks and subagents.

Repo

Problem

LLM Evaluation Harness

A reusable test suite that scores models and prompts, and blocks a merge when the scores drop.

  • 46pytest
  • 03RAGAS
  • 04DeepEval
  • 05Langfuse
  • 47OpenAI/Anthropic APIs
  • 28GitHub Actions

Repo

Problem
A prompt or model change can make answers worse without anyone noticing until users do.
Built
A reusable harness that scores models and prompts on curated datasets across accuracy, faithfulness, relevance and latency, with pluggable metrics and provider-agnostic adapters.
Hard part
Trusting the judge. I implemented LLM-as-judge and reference-based scoring with RAGAS and DeepEval, and calibrated the judge prompts against human labels to improve metric–human agreement.
Result
The harness runs in CI as a regression gate via GitHub Actions, blocking merges on score drops and logging per-run traces to Langfuse for diagnosis.

Repo

Problem
A naive Hugging Face pipeline makes poor use of the GPU: throughput is low and larger models don't fit.
Built
A self-hosted inference service with vLLM behind a FastAPI gateway, using continuous batching and PagedAttention.
Hard part
GPU memory and latency. I applied INT8/AWQ quantization and KV-cache tuning, then benchmarked throughput, latency percentiles and tokens/sec under concurrent load.
Result
~3x throughput over a naive Hugging Face pipeline, ~50% less GPU memory and ~40% lower p95 latency, enough to fit larger models on a single GPU. Prometheus metrics drive autoscaling and catch performance regressions.

MSc Research: Wendland's CSRBF in Kolmogorov–Arnold Networks (KAN)

A smaller, faster version of a newer neural network architecture. Research project at UCC, under Dr. Andreas Amann.

  • 48PyTorch
  • 52Kolmogorov–Arnold Networks
  • 53Radial basis functions
  • 54Regularization

Repo

Problem
Kolmogorov–Arnold Networks learn their own activation functions, but they're expensive to train.
Built
KAN alternatives in PyTorch that replace B-spline and Gaussian edge activations with compactly supported Wendland radial basis functions (a lighter building block that only switches on locally), with trainable centers and support radii.
Hard part
Keeping trainable radii stable, which I did with inverse-L2 regularization, and quantifying the sparsity–accuracy trade-off.
Result
Compared across six baselines.

Problem
Serverless apps are easy to deploy and hard to debug when they fail at 3 a.m.
Built
A modular Terraform stack for a serverless order service with a sync path (API Gateway → Lambda → DynamoDB) and an async path (SQS → worker Lambda + DLQ), on an S3-locked remote backend.
Hard part
Making failures visible, through structured JSON logging, metric filters and EMF custom metrics, with saved Logs Insights queries for latency percentiles, cold starts and request tracing.
